# 钓鱼游戏轻度化 + 社交排行榜优化流程图

目标：把游戏从多系统养成，收敛成“轻度钓鱼 + 图鉴收集 + 天气季节 + 失败后再来一次 + 省份排行榜”的完整闭环。

估算口径：

- 1 人日 = 8 人时。
- 默认 1 名熟悉当前项目的前端/小游戏开发者执行。
- 时间包含方案细化、代码修改、基础 UI、联调、自测。
- 不包含微信审核等待、服务器采购/备案、额外美术外包、复杂反作弊。
- 省份排行榜按“真实线上榜”估算；如果只做本地模拟榜，可减少约 4 到 6 人日。

## 1. 完整优化总流程

```mermaid
flowchart TD
  A[开始: 明确轻度化目标 0.5人日] --> B[系统取舍与入口重构 4.5人日]
  B --> C[核心钓鱼循环增强 4.0人日]
  C --> D[失败后再来一次与分享次数 2.5人日]
  D --> E[天气预报与季节接入 5.5人日]
  E --> F[排行榜与省份榜单 8.5人日]
  F --> G[数据埋点与数值调优 2.0人日]
  G --> H[兼容测试与发布验证 3.0人日]
  H --> I[完成轻度社交版 v1]

  B --> B1[删除/隐藏重系统]
  B --> B2[保留轻入口]
  C --> C1[缩短单局闭环]
  C --> C2[强化结果反馈]
  D --> D1[失败页]
  D --> D2[分享/等待/广告兜底]
  E --> E1[今日环境]
  E --> E2[未来预报]
  F --> F1[个人榜]
  F --> F2[省份榜]
  F --> F3[好友榜可选]
```

## 2. 外围系统取舍流程

```mermaid
flowchart TD
  A[现有顶部入口] --> B{是否服务轻度核心?}

  B -- 是 --> C[保留主入口]
  B -- 部分是 --> D[合并/降级]
  B -- 否 --> E[删除或隐藏]

  C --> C1[钓鱼主按钮: 保留]
  C --> C2[鱼饵/商店: 简化保留 1.0人日]
  C --> C3[图鉴: 强化保留 1.0人日]
  C --> C4[鱼竿: 简化成长保留 1.0人日]
  C --> C5[天气/季节: 保留 5.5人日]
  C --> C6[排行榜: 保留并重做 8.5人日]

  D --> D1[角色: 降级为外观 0.75人日]
  D --> D2[宠物: 降级为陪伴/外观 0.75人日]
  D --> D3[分享: 移到失败页和结果页 0.5人日]

  E --> E1[首饰: 删除或隐藏 0.5人日]
  E --> E2[复杂抽奖: 删除或改每日奖励 1.0人日]
  E --> E3[VIP自动: 删除或改免费辅助 0.5人日]
  E --> E4[兑换码: 隐藏到运营后台 0.25人日]
  E --> E5[假排行: 删除，改真实个人/省份榜 0.5人日]
```

## 3. 轻度核心单局流程

```mermaid
flowchart TD
  A[进入主界面] --> B[显示今日天气、剩余次数、当前鱼饵]
  B --> C{是否有钓鱼次数?}
  C -- 否 --> C1[进入失败/次数不足页]
  C1 --> C2[分享给朋友/等待恢复/广告兜底]
  C2 --> B

  C -- 是 --> D[点击抛竿]
  D --> E[扣除鱼饵或次数]
  E --> F[等待上钩: 受天气和鱼饵影响]
  F --> G{及时收线?}
  G -- 否 --> H[失败页: 还差一点，再来一次]
  H --> C1

  G -- 是 --> I[命中条小游戏]
  I --> J{命中成功?}
  J -- 否 --> H
  J -- 是 --> K[钓获结果]
  K --> L[更新金币、图鉴、最大重量、排行榜分数]
  L --> M[结果页: 分享战绩/继续钓鱼/查看图鉴]
  M --> B
```

## 4. 失败后分享获取次数流程

> 注意：这个流程建议做成“可选补充次数”，不要做成唯一继续方式。为了降低审核风险，失败后应至少提供一种非分享路径，比如自然恢复、每日免费次数、激励广告或消耗游戏内金币。

```mermaid
flowchart TD
  A[失败或次数用尽] --> B[失败页]
  B --> C[展示本局差距: 差1次命中/差1条稀有鱼/省榜差X分]
  C --> D{玩家选择}

  D --> D1[分享给朋友]
  D --> D2[等待自然恢复]
  D --> D3[消耗金币再来一次]
  D --> D4[观看激励广告 可选]

  D1 --> E1{分享是否成功回流?}
  E1 -- 是 --> F[增加1次机会 每日上限]
  E1 -- 否 --> G[不发奖励，提示可用其他方式]

  D2 --> H[倒计时恢复次数]
  D3 --> I[扣金币，增加1次机会]
  D4 --> J[广告完成，增加1次机会]

  F --> K[回到主界面]
  G --> K
  H --> K
  I --> K
  J --> K
```

## 5. 排行榜与省份榜单流程

```mermaid
flowchart TD
  A[钓获结算] --> B[计算本局分数]
  B --> B1[鱼稀有度分]
  B --> B2[重量分]
  B --> B3[天气/季节限定加分]
  B --> B4[连续命中加分]
  B1 --> C[生成 score]
  B2 --> C
  B3 --> C
  B4 --> C

  C --> D[本地更新个人最佳]
  C --> E{是否登录/授权}
  E -- 否 --> E1[仅显示个人记录，引导授权]
  E -- 是 --> F[提交成绩到后端]

  F --> G[后端校验]
  G --> G1[每日次数/分数范围校验]
  G --> G2[用户、省份、日期维度去重]
  G --> G3[保存 bestScore / totalScore / maxWeight]

  G3 --> H[返回排行数据]
  H --> I[全国榜]
  H --> J[省份榜]
  H --> K[好友榜 可选开放数据域]

  I --> L[排行榜页]
  J --> L
  K --> L
  L --> M[失败页/结果页展示: 你在本省超过X%玩家]
```

## 7. 推荐排期

| 版本 | 范围 | 人日 | 说明 |
|---|---|---:|---|
| v0.1 轻度内核 | 删减重系统、主循环、图鉴、鱼竿、商店 | 8 到 10d | 先让游戏不臃肿 |
| v0.2 天气季节 | 今日天气、预报、季节限定鱼、场景反馈 | 5 到 6d | 提升完整度和每日变化 |
| v0.3 分享次数 | 失败页、次数恢复、分享/兜底路径 | 2 到 3d | 做传播闭环 |
| v0.4 省份排行 | 后端、省份榜、分数模型、防作弊 | 6 到 8d | 形成羊了个羊式地域竞争 |
| v0.5 好友榜可选 | 微信开放数据域好友榜 | 2 到 3d | 如果微信版本优先再做 |
| v1.0 验收发布 | 埋点、兼容、真机、构建、文案检查 | 3 到 4d | 发布前稳定性 |

标准版合计：约 24 到 31 人日。

如果暂时不做真实后端省份榜，只做本地模拟排行榜，合计可压缩到约 17 到 22 人日。

## 8. 关键决策点

- 排行榜建议保留，但不要保留假机器人榜。轻度版要么做个人记录，要么做真实省份榜。
- 分享获次数建议保留，但不要作为唯一继续方式。失败后可以有分享、等待、金币、广告等多个入口。
- 抽奖、首饰、VIP 自动、兑换码建议从主界面删除，后续如有运营需要再隐藏式接入。
- 角色和宠物可以保留情感价值，但不要再叠复杂数值。
- 天气和季节用于“每日变化”和“限定收集”，不要堆太多倍率解释。
